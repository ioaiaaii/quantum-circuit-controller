# Thesis demonstration kit

Two worked examples that exercise QCC's workflow and observability surface on a
**single backend** (`fake_brisbane`, a 127-qubit Eagle r3 snapshot). The kit is
not an algorithm contribution — it shows the *tooling*: submit a circuit,
select a backend, read the calibration-aware score, tune the run through the
Circuit CRD, and watch the metrics move. Holding the backend fixed makes
circuit depth the variable that separates the two outcomes.

| Demo | Circuit | Depth (transpiled) | Outcome | What it shows |
|------|---------|-------------------|---------|---------------|
| 1. Signal survives | Deutsch | ~6 | ~97% on the correct peak | A shallow circuit is unaffected by stale calibration |
| 2. Degraded at depth | Shor (N=15, a=4) | ~1700 | ~27% → 29% (ideal 50%) | The Chapter 1 circuit: a deep circuit degrades; Tier-2 tuning trims gates and nudges the result, and QCC makes the loss visible |

These are starting points — point the same workflow at your own circuits to run
further experiments. The kit is the empirical basis for the backend-selection
and observability claims in the Architecture and Implementation chapters (R5:
calibration-aware evaluation; cross-boundary metric vocabulary).

## Layout

```
thesis/
├── algorithms/          # the quantum programs (the circuit source)
│   ├── deutsch.qasm     #   OpenQASM 3 — hand-written, deterministic
│   └── shor.py          #   Qiskit — period-finding for N=15, a=4 (the Ch1 circuit)
├── qpus/
│   ├── fake-brisbane.yaml  # Eagle r3 sim (kit default)
│   └── fake-fez.yaml       # Heron r2 sim (sibling of live ibm-fez)
├── circuits/            # Circuit CRDs: each wraps one algorithm + run config
│   ├── deutsch.yaml
│   ├── shor-baseline.yaml      # opt 1, no Tier-2  — sim-side (fake_brisbane)
│   ├── shor-tuned.yaml         # opt 3 + Tier-2    — sim-side (fake_brisbane)
│   ├── shor-v2.yaml            # opt 3, no Tier-2  — real-hw (ibm-kingston)
│   └── shor-v3.yaml            # opt 3 + scheduling_method:alap — real-hw (ibm-kingston)
└── render.py            # regenerates circuits/*.yaml from algorithms/
```

**algorithms vs circuits.** An *algorithm* file is the quantum program. A
*Circuit* (the `kind: Circuit` YAML) is the Kubernetes resource that says "run
this source, on this backend, with these options." The CRD inlines the source
in `spec.source.body` because the API has no ConfigMap-reference field — so the
manifests carry a verbatim copy generated by `render.py`. Edit an algorithm,
then re-run `python3 render.py` to refresh the manifests.

## Two ways to run

**CLI** — for the quick, untuned runs (Deutsch, Shor baseline):

```bash
qcc run examples/thesis/algorithms/deutsch.qasm --backend fake_brisbane --shots 4096
qcc run examples/thesis/algorithms/shor.py      --backend fake_brisbane --shots 4096
```

**Manifests** — required for the Tier-2 tuning demo, because the
`transpile:`/`execute:` passthrough blocks have no CLI flags:

```bash
kubectl apply -f examples/thesis/qpus/fake-brisbane.yaml
kubectl apply -f examples/thesis/circuits/shor-baseline.yaml
kubectl apply -f examples/thesis/circuits/shor-tuned.yaml
```

Inspect any run with the rich card:

```bash
qcc get circuit shor-tuned
```

## The Tier-2 story (Circuit CRD tuning)

The Circuit `spec` is two-tier. **Tier 1** is QCC's typed vocabulary
(`mode`, `shots`, `optimizationLevel`, `backendSelector`). **Tier 2** is the
`transpile` and `execute` passthrough blocks, forwarded verbatim as keyword
arguments to Qiskit's `transpile()` and the backend's `run()`. This is how a
user reaches any vendor-SDK knob without a CRD or controller change.

### Shor: a degraded result, and the metrics that explain it

This is the author's coursework circuit — factoring N=15 with a=4 (order 2,
so r=2 and 15 = 3×5) — the same one whose `ibm_brisbane`/`ibm_sherbrooke` runs
open Chapter 1. The ideal result is two peaks (`0000` and `1000`) at 50% each;
on `fake_brisbane` the correct mass collapses to ~27%, the signature of a
circuit run past the device's error budget.

`shor-baseline.yaml` (opt 1) vs `shor-tuned.yaml` (opt 3 + Tier-2):

| | Depth | 2Q gates | Correct-peak mass |
|---|------:|---------:|------------------:|
| baseline | 1785 | 477 | 26.7% |
| tuned    | 1703 | 433 | 29.0% |

The Tier-2 block trims two-qubit gates and depth and lowers QCC's error-exposure
score, nudging the correct mass up a couple of points — but at this depth the
result stays degraded. That is the point: QCC's score flags the loss *before*
execution, the metrics move when the circuit is tuned, and the gap between the
two peaks and the ~50% ideal is legible end to end. Tuning is observable; the
physical ceiling is real.

All numbers use the pinned `seed_transpiler: 42` / `seed_simulator: 42` in the
manifests and are reproducible on the bundled `fake_brisbane` snapshot.

## Capturing figures

`freeze` renders terminal output to PNG. To include the command line above the
output, print it as the first line:

```bash
freeze -t github --window \
  -x "printf '\033[36m❯\033[0m qcc get circuit shor-tuned\n'; qcc get circuit shor-tuned" \
  -o ./docs/shor-tuned.png
```

Suggested captures: `qcc draw` on Deutsch (small enough to read), the
`qcc get circuit` cards for each run, and the Grafana
`qcc_circuit_result_count` histograms side by side for the Shor
baseline-vs-tuned pair.
